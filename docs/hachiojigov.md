# 子育て世帯向け 医療・福祉情報ナビ 要件定義書

版：1
作成日：2026-11-06
対象：MVP（八王子市の子育て世帯向け）

## 1. 目的と背景

### 1.1 背景と課題

国や自治体は医療・福祉・子育ての情報を数多く公開していますが、利用者には次のような壁があります。

- 制度が国・都・市に分かれていて、自分の家に関係するものがどれか分からない。何を調べればよいかも分からない。
- 申請に必要なものや締切が分かりにくく、書類をそろえるのが大変。
- 汎用のAIチャットに聞くと、家族の情報を毎回説明しなければならず、答えの根拠も分からない。

### 1.2 目的

国と自治体が公開している医療・福祉・子育ての情報をベクトルDBに集め、世帯ごとに合うものだけをダッシュボードで提示し、出典つきでAIに相談できるスマホ向けPWAを作る。利用者が次の4つをできるようにする。

1. 自分の家に関係する制度を、調べ方を知らなくても見つけられる。
2. 申請に必要な内容・書類・締切を確認し、準備を進められる。
3. 悩みを自由に相談し、公的資料を根拠にした答えを出典つきで受け取れる。

### 1.3 ビジョン

行政の情報と医療・福祉を掛け合わせたソリューションとして、最終的には国民全員が使えるサービスにする。MVPでは対象を絞り、情報収集と回答の質を確かめてから広げる。

### 1.4 差別化のポイント

ChatGPTやClaudeでも相談はできるが、家族の情報を毎回自分で打ち込まないと、自分に合った答えは返ってこない。また、利用者のデジタル活用スキルに応じてプロンプトの質が異なり、安定した回答を得られない。本サービスは世帯の情報を前もって持ち、公的な資料だけを根拠に答える。

1. **出典つきで答えるRAG**：回答や表示する制度には、必ず根拠の公的資料（URL・取得日）を付ける。
2. **複雑な医療費にも対応**：世帯の医療費・薬・助成制度をまとめて管理できる。写真から領収書を読み取り、申請に必要な情報をまとめておける。その情報を基に、申請できる制度を発見したり、その制度の申請に必要な情報をまとめて提示する。
3. **いつでも相談できる窓口**：文字だけでなく、画像でも質問できる。

## 2. スコープ

### 2.1 MVPの範囲

MVPは「八王子市に住む、子どもを持つ親」だけに絞る。

| 項目 | MVPでやること | MVPではやらないこと（将来） |
| --- | --- | --- |
| 対象ユーザー | 子どもを持つ親 | 高齢者・介護世帯、障害者、単身世帯など全世帯 |
| 対象地域 | 東京都八王子市（現時点の情報） | 他の市区町村・全国 |
| 情報源 | 国（厚生労働省など）・東京都・八王子市の公開ページとPDF | 自治体ごとの自動収集の全国展開 |
| 情報の種類 | 子育て支援策・イベント・施策、子どもの医療費助成、予防接種、外来・救急の案内 | 介護保険、障害福祉など |
| 外部連携 | なし | マイナポータルAPI |

### 2.2 MVPで扱わないこと

- 八王子市以外の市区町村への対応、全国展開
- 子育て世帯以外（なお子育てに対する福祉支援は含む）への対象拡大（介護、障害福祉、高齢者など）
- マイナポータルAPIなどの外部連携（MVPでは医療費データの形を将来の連携に合わせておくだけにする）
- 妊娠・出産の制度（妊婦健診など）は「子育て」に含める。つまりMVPとして取り扱う。

## 3. 想定ユーザーとユースケース

想定ユーザーは、八王子市に住む忙しい子育て中の親です。子ども向けの支援策・イベント・施策を調べたいが、何を調べればよいか分からない、というのが一番の悩みです。登録や入力の手間を負担に感じやすいため、最初は最低限の入力で使い始められることを重視します。

| ID | ユースケース | 内容 | 関連機能 |
| --- | --- | --- | --- |
| UC1 | はじめて使う | ログインせずに郵便番号と子どもの年齢だけを入れ、すぐに自分の家に関係する制度を見る | F1・F2 |
| UC2 | ダッシュボードを見る | おすすめの制度、進行中の申請の途中経過、締切を確認し、タップして詳細を見る | F4 |
| UC3 | 申請の準備をする | 必要な書類や内容を確認し、必要ならAIに手伝ってもらう | F4・F5 |
| UC4 | AIに相談する | 自由に悩みを入力し、公的資料を根拠にした解決策を出典つきで受け取る。提案された内容をダッシュボードに追加できる | F5 |
| UC5 | 医療費をまとめる | 領収書を撮影して医療費を記録し、助成や申請に必要な形でまとめる | F6 |

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| RAG | 検索で取り出した資料を根拠に、AIが回答を作る仕組み |
| ベクトルDB | 文章の意味を数値（ベクトル）にして保存し、意味の近いものを検索できるデータベース |
| チャンク | 公的資料を検索しやすい大きさに分割した断片。出典URLや取得日などを付けて保存する |
| 制度カード | ダッシュボードに表示する、制度1件ぶんの要約 |
| PWA | ホーム画面に追加して、アプリのように使えるWebアプリ |
| 要配慮個人情報 | 障がいの有無など、個人情報保護法で特に慎重な扱いが求められる情報。取得前に本人の同意が必要 |
| 自治体コード | 市区町村を表すコード。情報の絞り込みと、対応自治体の追加に使う |

## 5. 利用の流れ

1. 初めてアプリを開くと、ログイン画面が表示される。サービスの利用には会員登録が必要。
2. 郵便番号を入力し、続けて子どもの人数と年齢を入力する。ほかの項目は「あとで入力する」を選べる（F2）。
3. ダッシュボードに、世帯に合う制度、進行中の申請、締切が表示される。カードをタップすると詳細を見られる（F4）。
4. 詳細画面から「AIに聞く」を押すか、AI相談を開いて自由に質問する。回答には出典が付く（F5）。
5. AIが提案した制度は「ダッシュボードに追加」で反映できる（F5）。
7. 急な病気・けがのときは「急な病気・けが」の入口から、固定の案内（相談窓口・医療機関・持ち物）を見る（F7）。

## 6. 機能要件

### 6.1 機能一覧

受け入れ条件の詳細（EARS形式）は、別ドキュメント「Kiro用プロジェクト仕様」の4章にあります。

| ID | 機能 | 概要 | 優先度 |
| --- | --- | --- | --- |
| F1 | ユーザー登録・ログイン | 匿名で使い始め、あとから本登録（Google／メール）してデータを引き継ぐ | 必須 |
| F2 | 初回入力（オンボーディング） | 郵便番号と子どもの人数・年齢を最小限で入力。残りはあとから追加 | 必須 |
| F3 | 公的情報の収集・更新 | 公的サイトとPDFを定期取得し、出典つきでベクトルDBに保存（運営側） | 必須 |
| F4 | ダッシュボード | 世帯に合う制度、進行中の申請、締切を表示。詳細画面へ | 必須 |
| F5 | AI相談 | 出典つきRAGチャット。画像でも質問でき、提案をダッシュボードに追加できる | 必須 |
| F6 | 医療費のまとめ | 領収書の写真から読み取り、集計し、申請に使える形にまとめる | 必須 |
| F7 | 急な病気・けがへの対応 | 夜間の発熱などで、固定の案内・医療機関の地図・持ち物を表示 | 必須 |
| F8 | 締切の通知 | 締切が近い申請や、保存した制度の更新を知らせる | できれば |
| F9 | 世帯情報の管理と削除 | 世帯情報の編集と、アカウント削除（全データの削除） | できれば（公開準備で対応） |

### 6.2 機能ごとの要件

#### F1. ユーザー登録・ログイン
**F1-2は廃止。サービスの利用には必ず会員登録が必要**
- F1-1　初めてアプリを開いたとき、ログイン画面を出さずに匿名アカウントで使い始められること。
- F1-2　一定回数（例：AIとのやり取り3回）利用したら、データを失わないための登録案内を表示すること。
- F1-3　Googleアカウントまたはメールで本登録でき、匿名で入力した世帯情報・チャット履歴・申請状況をすべて引き継ぐこと。
- F1-4　登録済みユーザーが別の端末でログインしたとき、同じデータを表示すること。

#### F2. 初回入力（オンボーディング）

忙しい親の負担を減らすため、初回に聞くのは最低限にして、残りはあとから追加できるようにする。

| 入力項目 | 初回必須 | あとから追加 |
| --- | --- | --- |
| 住んでいる場所の郵便番号 | する |  |
| 子どもの人数と年齢 | する |  |
| 子どもの性別 |  | する |
| ユーザー自身の名前・年齢・性別 |  | する |
| 子どもの現在の状況（チップ選択＋自由入力） |  | する |

- F2-1　7桁の郵便番号から都道府県・市区町村・町名を表示し、参照する情報源（国・東京都・八王子市）を示すこと。
- F2-2　八王子市外の郵便番号の場合は「現在は八王子市のみ対応」と伝え、国の制度だけで続けるかを選べること。
- F2-3　存在しない郵便番号は、入力欄のそばにエラーを表示して次へ進ませないこと。
- F2-4　子どもの状況は、「障がいの有無」「サッカーが好き」「留学を考えている」のような一般的な特徴をチップで複数選べ、自由入力もできること。
- F2-5　「あとで入力する」を選んだら、必須項目だけでダッシュボードを作ること。
- F2-6　障がいなど健康に関わる項目を初めて入力するときは、利用目的を示して同意を得てから保存すること。

#### F3. 公的情報の収集・更新（運営側）

- F3-1　定期的に、登録済みの情報源（八王子市・東京都・厚生労働省などのページとPDF）を取得すること。
- F3-2　取得した内容が前回と同じなら再処理しないこと（ハッシュで判定）。
- F3-3　内容が変わったものと新しいものは、制度ごとの形式的なフォーマット（制度名・対象・内容・申請方法・必要書類・締切・窓口・出典）に整理し、分割・埋め込みを作ってベクトルDBに保存すること。
- F3-4　すべてのチャンクに、出典URL・取得日・自治体コード・対象（年齢帯など）・カテゴリを付けること。
- F3-5　取得に失敗したときは、前回のデータを残したままエラーを記録すること。
- F3-6　情報源のページが削除されたときは、そのチャンクを検索対象から外すこと。

#### F4. ダッシュボード

- F4-1　世帯情報で絞り込んだ「おすすめの制度」「進行中の申請と途中経過」「締切」を表示すること。
- F4-2　各制度カードに、国・都・市のどれの制度か、対象の家族、一行の要約、出典と更新日を表示すること。
- F4-3　カードをタップすると、詳細画面（要点、手続きの流れ、必要なもののチェックリスト、窓口、出典一覧）を表示すること。
- F4-4　詳細画面の「AIに聞く」で、その制度を話題にしたチャットを開始し、申請内容の記入を補助すること。
- F4-5　申請を「進行中」にしたら、その申請の締切とやることをダッシュボード上部に表示すること。
- F4-6　カテゴリで絞り込んだら、該当する制度だけを表示すること。

#### F5. AI相談（出典つきRAGチャット）

- F5-1　質問を送信したら、世帯情報（自治体・子どもの年齢など）で絞ったベクトル検索を行い、その結果だけを根拠に回答すること。
- F5-2　回答本文に \[1\] のような引用番号を入れ、その下に出典（資料名・URL）を表示すること。
- F5-3　引用番号が検索結果に存在しないチャンクを指していたら、その引用を表示しないこと。
- F5-4　関連する公的資料が見つからないときは、推測で答えず、「資料が見つからない」と伝えて問い合わせ先を案内すること。
- F5-5　画像（通知書や書類の写真など）を添付して質問できること。
- F5-6　回答で制度を提案したら「ダッシュボードに追加」ボタンを表示し、押されたら反映すること。
- F5-7　次に聞けそうな質問の候補をチップで表示すること。
- F5-8　病気の診断や治療の判断を求められたときは、診断をせず、医師や相談窓口への相談をすすめること。

#### F6. 医療費のまとめ（写真から読み取り）

- F6-1　領収書の写真をアップロードしたら、日付・医療機関名・金額・対象者を読み取り、確認画面に表示すること。
- F6-2　読み取り結果を確認・修正して保存したら、世帯の医療費記録に追加し、期間・家族ごとに集計すること。
- F6-3　読み取れない項目は空欄にして、手入力を促すこと。
- F6-4　記録が助成や申請の対象になりそうなときは、関係する制度を提示し、必要な情報をまとめて「あとは入力するだけ」の状態にすること。
- F6-5　読み取りが完了したら、元の画像を一定期間後に自動で削除すること。

#### F7. 急な病気・けがへの対応（夜間の発熱など）
**これはMVPでは実装しない。いちど置いておく**
- F7-1　「急な病気・けが」の入口では、AIの生成を使わず、あらかじめ用意した案内（子どもの医療電話相談 #8000、救急相談 #7119、救急車 119、医療機関を探せる公的サービス）を表示すること。
- F7-2　外来を探すときは、現在地または住所の近くの医療機関を地図で示すこと。
- F7-3　受診時の持ち物（マイナ保険証、医療証など）をチェックリストで示すこと。
- F7-4　チャットで緊急性の高い言葉（意識がない、けいれんなど）を検知したら、回答より先に119番などの緊急連絡先を表示すること。

#### F8. 締切の通知（できれば）

- F8-1　進行中の申請の締切が近づいたら、プッシュ通知を送ること（ユーザーが許可した場合のみ）。
- F8-2　公的情報が更新され、ユーザーが保存した制度に変更があったら、アプリ内でお知らせすること。

#### F9. 世帯情報の管理と削除（できれば）

- F9-1　世帯情報を変更したら、ダッシュボードのおすすめを更新すること。
- F9-2　アカウント削除を実行したら、世帯情報・チャット履歴・医療費記録・画像をすべて削除すること。

## 7. データ要件

### 7.1 扱うデータ

| データ | 主な項目 | 閲覧・更新できる人 |
| --- | --- | --- |
| 世帯情報 | 郵便番号、自治体コード、保護者の属性（任意）、同意の記録 | 本人のみ |
| 子どもの情報 | 年齢（または生年月）、性別（任意）、状況チップ、自由入力 | 本人のみ |
| 申請状況 | 制度ID、状態（未着手・進行中・完了）、締切、やること | 本人のみ |
| 医療費記録 | 日付、医療機関名、金額、対象者、元画像 | 本人のみ |
| チャット履歴 | 役割、本文、引用したチャンク | 本人のみ |
| 制度情報 | 制度名、対象、内容、申請方法、必要書類、締切、窓口、年齢区分、自治体コード、レベル（国・都・市） | 誰でも閲覧可。更新は収集系のみ |
| チャンク | 本文、埋め込みベクトル、制度ID、出典URL、取得日、ハッシュなど | APIと収集系のみ |
| 情報源 | 情報源URL、自治体コード、取得頻度、前回のハッシュと取得日時 | 収集系のみ |

### 7.2 公的情報に付けるメタデータ

出典URL、取得日、自治体コード、レベル（国・都・市）、対象（年齢区分）、カテゴリ、ハッシュ。年齢の範囲は、検索で絞り込みやすいよう区分のタグで持たせる。

### 7.3 保持と削除

- アカウントを削除したら、世帯情報・チャット履歴・医療費記録・画像をすべて削除する。
- 領収書などの画像は、読み取り後に一定期間で自動削除する（期間は未決事項）。

## 8. 非機能要件

### 8.1 プライバシー・セキュリティ

- 障がいの有無などは個人情報保護法の「要配慮個人情報」にあたるため、取得前に本人の同意を得る。利用規約とプライバシーポリシーを用意する。
- ユーザーデータは、本人しか読み書きできないよう制限する。
- データは日本国内（東京リージョン）に置く。
- LLMには名前など個人を特定できる情報を送らず、回答に必要な属性（自治体・子どもの年齢帯など）だけを渡す。
- APIキーや認証情報はコードに書かず、専用の仕組みで管理する。

### 8.2 AIの安全性

- AIは公的資料にない内容を断定しない。根拠がないときは「分からない」と答える。
- 病気の診断・治療の判断はしない。画面に「診断や治療の判断は医師に」と常に表示する。
- 緊急時の案内（F7）はAIに生成させず、固定の内容で表示する。
- すべての制度情報に出典と取得日を表示し、「最新の情報は窓口で確認を」と添える。

### 8.3 使いやすさ・アクセシビリティ

- スマホの縦画面（幅390px前後）を基準に設計し、ホーム画面に追加できるPWAにする。
- タップできる部分は44px以上、文字と背景のコントラスト比は4.5:1以上にする。
- 主なメニュー（ホーム・さがす・AI相談・わが家）は画面下部のタブバーに置く。
- 初回入力は最小限にし、「あとで入力する」を選べるようにする。

### 8.4 性能・可用性

- AIの回答はストリーミングで表示し、待ち時間を短く感じさせる。
- 一度開いた制度情報や緊急時の案内は、電波が弱くても表示できるようにする。

### 8.5 運用・コスト

- 個人開発の予算内で運用するため、常時起動のサーバーは使わず、使った分だけ課金されるサービスを選ぶ。予算アラートを設定する。
- 公的情報は定期的に取得し、変更があったものだけを更新する。

### 8.6 拡張性・保守性

- 自治体コードごとに情報源を登録するだけで、対応する自治体を増やせる設計にする。
- AIのモデル名やリージョンはコードに直接書かず、設定に出して差し替えやすくする。

### 8.7 対応環境

- パソコンとスマホのブラウザとPWA。iPhoneのプッシュ通知は、ホーム画面に追加したPWAのみ受け取れる。

## 10. MVPの完了条件（案）

- 八王子市・東京都・国の子育て関連の情報が収集され、出典URLと取得日つきで検索できる。
- AI相談の回答すべてに出典が付き、引用番号が検索結果と一致する。
- 質問と期待する出典の評価セット（20問程度）で、回答の質を確かめている。
- 匿名のまま、郵便番号と子どもの年齢だけでダッシュボードが表示される。
- 緊急時の案内が、AIの生成を介さず固定の内容で表示される。
- 必須機能（F1〜F7）の受け入れ条件を満たしている。

## 11. リスクと対策

| リスク | 対策 |
| --- | --- |
| 公的情報が古い・誤って取り込まれる | 差分取得と定期更新。すべての情報に出典と取得日を表示し、「最新は窓口で確認を」と添える |
| AIが根拠のない回答や医療判断をしてしまう | 検索結果だけを根拠にし、引用を検証する。診断はしない。見つからないときは「分からない」と答える |
| 緊急時に誤った案内をしてしまう | AIの生成を使わず、固定の案内を表示する |
| 要配慮個人情報の取り扱い | 同意の取得、本人のみ読み書きできる制限、東京リージョン、LLMに個人を特定できる情報を送らない、画像の自動削除 |
| 自治体を増やすときの収集・更新の手間 | 自治体コードごとに情報源を登録するだけで増やせる設計にする。まず八王子市で質を確かめる |
| 利用料金が増える | 使った分だけ課金されるサービスを選び、予算アラートを設定する |

## 12. 開発の進め方

「資料を集める」→「根拠つきで答える」→「世帯に合わせて見せる」の順に作る。RAGの回答の質を早めに確かめるため、画面より先に情報収集を作る。

1. フェーズ0：土台（Google Cloudプロジェクト、予算アラート、開発環境）
2. フェーズ1：情報の収集（F3）
3. フェーズ2：出典つきRAG（F5の中心。評価セットで回答の質を測る）
4. フェーズ3：アプリ画面（F1・F2・F4・F5、PWA対応）
5. フェーズ4：緊急時と医療費（F7・F6、画像つきの質問）
6. フェーズ5：仕上げ（F8・F9、利用規約・プライバシーポリシー・同意画面）
